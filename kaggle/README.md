# Modegen: сайт → собственная сессия Kaggle

Страница: https://modegen.ru/ai-platform/ (GitHub Pages, статический сайт).
Фронтенд больше не вызывает публичный Space IDM-VTON или Gemini.

## Ручной запуск

1. Импортируйте `ai-platform/modegen_kaggle_web.ipynb` в **новый приватный** Kaggle notebook.
2. GPU T4 (T4 ×2 тоже подходит), Internet On. Input не нужен.
3. **Run All в редакторе**, не Save & Run All. Последняя ячейка остаётся работающей.
4. На странице студии введите выданные адрес `https://….gradio.live` и ключ, нажмите «Подключить».
5. Выберите модель или загрузите человека; загрузите разложенный верх; создайте кадр.
6. Скачайте результат. По окончании остановите **GPU-сессию Kaggle**.

Ключ не отправлять в чат, не сохранять в GitHub или публичном выводе notebook.
Он генерируется для каждой сессии, хранится в памяти сервера и вкладки сайта.
Стандартные пользовательские cookies и HF-токены серверу не передаются.

## Какая модель

Последний полученный успешный GPU-тест: **FASHN v1.1** (FASHN VTON 1.5,
закреплённые веса `7720683168567eb5a2a4c67f15116c6e29c83ded`).
FP32; seed42; 30 steps; CFG1.5; segmentation_free=True; tops/flat-lay;
attention query chunk512; parser/DWPose на CPU. Нового обучения и LoRA нет.
`engine.py` сохраняет функции загрузки модели и attention из проверенного запуска.
Флаг маски из ещё не проверенного v1.2 не используется.

На предыдущем фото модель теряла логотип, поэтому это экспериментальный пилот,
не подтверждённое качество фото товара. Интеграция не улучшает веса модели.
Низ, платья, смена фона/формата не предлагаются как проверенные возможности.

## Временная сессия, не постоянный продакшен

Gradio 5.49.1 создаёт HTTPS-туннель в Kaggle. Адрес/ключ вводятся владельцем
в свою вкладку. Другие посетители сайта не получают их из опубликованного кода.
До 6 попыток; один inference одновременно; очередь максимум2;
сервер закрывается через30 минут простоя или2 часа (после текущего inference).
Эти пределы не отключают саму GPU-сессию Kaggle: её нужно остановить вручную.
Автоперезапусков notebook/генерации и обучения нет. Оплата не подключается.

API принимает JSON с base64 изображениями, возвращает PNG в JSON/SSE.
Bearer-ключ проверяется до разбора/постановки задания в очередь. Произвольные
загрузки, публичные файлы и остальные маршруты закрыты. JPG/PNG/WebP ≤8MiB,
≤16MP, лимит тела24MiB. Фото не сохраняются в файлы на сервере; временно
обрабатываются в RAM и очереди Gradio. Галерея — IndexedDB браузера.
Туннель проксирует трафик; это не прямое соединение без третьей стороны.

Регистрация на статическом сайте — локальный тестовый профиль, а не серверная
система аккаунтов. Новые пароли хешируются PBKDF2; старый локальный plaintext
мигрирует только при успешном входе. Это не авторизация GPU: её обеспечивает
отдельный ключ. Ранее сохранённые старой страницей данные не удаляются.
Аналитика и прежний встроенный HF-токен убраны из студии. Старый публичный
HF-токен стоит отозвать в Hugging Face: удаление из файла не очищает историю git.

## Проверки и ограничения

- `python -m pytest tests/test_bridge.py`: реальный локальный Gradio HTTP/SSE,
  авторизация, CORS, неверные фото, параметры, лимит, точное встраивание notebook.
- `node --test tests/client.test.mjs`: адреса, события SSE, Bearer-заголовок, отсутствие автоповторов.
- Ручной браузерный тест на localhost: вход гостем, плохой/верный ключ,
  загрузка, выбор модели, ответ, PNG-скачивание, галерея. CPU-заглушка помечена
  `TRANSPORT TEST ONLY / NOT A MODEL GENERATION`.
- Реальный GPU-путь через новый notebook **ещё не выполнен**. Потребуются
  первый ручной запуск и проверка туннеля на Kaggle. Локальный тест не доказывает
  доступность туннеля из Kaggle или качество новых генераций.

Сборка: `python kaggle/build_notebook.py`. Фото, веса и секреты в notebook не входят.
Локальный CPU-preview: `python tests/preview.py` (только 127.0.0.1, не публиковать как модель).

Источники: [Gradio sharing](https://www.gradio.app/guides/sharing-your-app),
[HTTP/SSE API](https://www.gradio.app/guides/querying-gradio-apps-with-curl),
[FASHN](https://github.com/fashn-AI/fashn-vton-1.5/tree/7c0f10af3f91ad4048fe9729c470a13ef905d25a).
Лицензии генератора и его компонентов проверяются отдельно; генератор Apache-2.0
не означает, что весь pipeline имеет одну лицензию.
