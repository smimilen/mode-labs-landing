## 1. О проекте

**Mode(gen)** — сервис AI-фотосессий для продавцов маркетплейсов (Wildberries,
Ozon, Яндекс Маркет). Продавец загружает фото одежды с вешалки — сервис
"надевает" её на AI-модель.

- **Домен:** modegen.ru

  Instagram @modegen.ru

## 3. Ключевые технические уроки

- **GitHub Pages + Jekyll:** `.nojekyll` в корне репо обязателен.
- **DNS апекса под GitHub Pages должен указывать ИСКЛЮЧИТЕЛЬНО** на 4 IP
  GitHub — любая посторонняя A/AAAA-запись на самом `modegen.ru.` (не на
  поддоменах) ломает автовыпуск SSL-сертификата. См. раздел 2 — это уже
  дважды случалось.
- **`style.css` перегружен `!important`** — новые страницы делаются
  автономными, со своим `<style>`, без подключения `style.css`.
- **GitHub Secret Scanning** блокирует пуш файлов с явными API-токенами —
  обходили разбиением строки (`hf_...` собирается через `.join()`). HF-токен
  для клиентских вызовов к HF Space лежит в `ai-platform/index.html` именно
  так, это осознанное решение (нужен на клиенте для вызова Gradio API),
  трогать не нужно без явного запроса.
- **Деплой на сайт** теперь можно делать обычным `git push` (через `gh`),
  а не только через Contents API — проще и надёжнее.
- Если после `_prepare_dataset`-подобных скриптов картинки/симлинки
  превращаются в битые ссылки после zip/unzip на Kaggle — см. функцию
  `_repair_image_cloth_symlinks_if_needed()` в `training/2_resume_densepose.py`
  как образец, как это чинится (перекачка исходника и пересоздание ссылок).

## 4. LoRA-дообучение IDM-VTON — сильно обновлено в этой сессии

⚠️ Старый контекст-файл описывал это как "черновой непроверенный скрипт" —
это устарело. Реальное состояние на конец сессии:

**Пайплайн полностью задокументирован и лежит в репозитории:**
`training/1_prepare_dataset.py`, `training/2_resume_densepose.py`,
`training/3_train_lora.py`, `training/README.md` (там же — таблица
соответствия файлов ноутбукам на Kaggle и текущий статус каждого шага).

**Прогресс:**
1. `1_prepare_dataset.py` (ноутбук `notebookcde6045e8e`) — упёрся в
   12-часовой лимит Kaggle. agnostic-mask досчитались полностью (train+test),
   image-densepose — частично.
2. `2_resume_densepose.py` (ноутбук `notebookd4fbf8b5b7`) — ✅ выполнен
   успешно. Весь датасет VITON-HD предобработан: train 11647 пар, test 2032
   пары, все нужные подпапки (image, cloth, agnostic-mask, image-densepose)
   готовы.
3. `3_train_lora.py` (ноутбук `notebookea97a06e7c`) — архитектурно сверен с
   реальным кодом `github.com/yisol/IDM-VTON` (TryonNet + GarmentNet +
   IP-Adapter + два текстовых энкодера SDXL, 13-канальный латент — не
   наивный MSE на голом UNet). За эту сессию найдены и исправлены прямо в
   репозитории (коммиты `022a08f`, `b6065bf`, `32e886c`) три причины падения:
   - Input-ноутбук с датасетом не был подключён через "Add Input" (сделали).
   - Баг в `restore_dataset()`: искал `_output_.zip` только на один уровень
     вложенности в `/kaggle/input/`, а Kaggle монтирует output подключённого
     ноутбука на несколько уровней глубже — исправлено на рекурсивный glob.
   - `ImportError: cannot import name 'cached_download' from 'huggingface_hub'`
     — `diffusers==0.25.0` несовместим со свежим `huggingface_hub`,
     предустановленным на образе Kaggle — исправлено явным пином
     `huggingface_hub==0.20.3` в `install_deps()`.
   - `RuntimeError: CUDA Setup failed despite GPU being available` —
     `bitsandbytes==0.39.0` падает прямо при импорте на текущем CUDA-образе
     Kaggle, а `peft.get_peft_model()` безусловно пытается его импортировать,
     если пакет вообще установлен (наш собственный `try/except` вокруг
     bitsandbytes в `train()` тут не спасает — ошибка происходит раньше,
     внутри `apply_lora()`). Исправлено — `bitsandbytes` больше не
     устанавливается вообще, используется обычный `AdamW` (для LoRA разница
     в VRAM незначительна, обучаются только маленькие adapter-веса).
   - **На конец сессии:** все четыре фикса внесены, но прогон с ними ещё не
     подтверждён до конца (не видели строк вида `Шаг 50/1000 · loss=...`) —
     нужно перезапустить с обновлённым скриптом и проверить лог заново в
     начале следующей сессии.

**Известные ограничения (подробнее в `training/README.md`):**
- Датасет VITON-HD — CC BY-NC 4.0 (только некоммерческое использование).
  Для коммерческой версии — дообучение на собственных данных платформы.
- Если `vitonhd_train_tagged.json` не найден в архиве, подписи дефолтные
  (`{}`/условно "shirts") — качество текстового кондиционирования ниже, чем
  с настоящими тегами.
- VRAM на бесплатном T4 (15-16GB) — на пределе даже с LoRA/fp16/gradient
  checkpointing/8-bit Adam. Дефолты (512×384, batch=1) — минимум, не
  "рекомендуемое качество".
- Датасет и чекпоинты живут только в Kaggle Notebook Output — ничего не
  сохранено персистентно вне Kaggle. Финальную LoRA после успешного
  обучения нужно будет скачать и залить в свой HuggingFace-репозиторий.
- Обучение требует GPU — реальный прогон должен идти на Kaggle (30
  GPU-часов/неделю бесплатно) или другом облаке, не локально.
